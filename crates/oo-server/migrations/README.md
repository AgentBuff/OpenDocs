# Server migrations

sqlx 按**文件名字典序**执行本目录下的 `.sql` 迁移，并在数据库 `_sqlx_migrations`
表中记录已应用版本；因此编号出现空洞没有运行时影响。

## 编号说明

当前序列为 `0001–0006`、`0008`、`0009`，**跳过 `0007`**。仓库在 2026-08 重新初始化
（git 历史仅保留 5 个提交），0007 在旧历史中的内容与跳号原因已不可考。

处理约定：

- **不回收空号**：新迁移从 `0010` 起继续编号。回收编号会让"同一编号在不同环境指向
  不同迁移集"，破坏 `_sqlx_migrations` 的可比性；
- 若未来考古出 0007 原文且仍有价值，以新编号重新提交并注明来历。

## 新增迁移的纪律

1. 破坏式演进：一次性复制/删除旧列旧表（见 `0005_command_log.sql`、
   `0008_canonical_artifact_storage.sql`），不保留兼容视图或双读双写；
2. 迁移文件一旦合入 main 即视为不可变——需要变更就追加新迁移；
3. 每个 schema 变更同步检查 `oo-schema` 的版本字段与
   `web/packages/schema/src/artifact.ts` 边界校验。
